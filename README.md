## 改装、装备加成和鱼线物品耐久（0.43.0）

商店最左侧新增“starter's shop／改装”栏目。改装页显示鱼竿示意图、一个鱼线槽和一个渔轮槽，两者可同时装备。点击槽位，从背包或任意已解锁仓库选择装备；装上后移出原格子，不再占用背包/仓库空间。更换时旧件放入新件腾出的格子；直接卸下优先寻找已解锁仓库，再找背包，完全没有连续空位就取消。钓鱼尚未结束（含收竿动画）时只能查看，不能装卸。

| 装备 | 韧性增加 | 收线基础速度增加 | 鱼主动移速降低 | 物品满耐久 |
|---|---:|---:|---:|---:|
| 1号鱼线 | 4 | 0.1米/秒 | 1% | 20 |
| 2号鱼线 | 10 | 0.1米/秒 | 3% | 40 |
| 3号鱼线 | 25 | 0.1米/秒 | 3% | 20 |
| 1号渔轮-初学者 | 0 | 0.15米/秒 | 2% | 不消耗 |

装备加速先加到3.75米/秒的基础速度，再乘角度效率。例如鱼线＋渔轮为4米/秒，120%效率为4.8米/秒。鱼移速减幅相加，只降低鱼主动挣扎速度，不改变原鱼资料和收线牵引计算。线韧性每竿从新上限104/110/125开始，仍在0.95秒后每0.1秒恢复2.5点，恢复到新上限；黄/橙/红阈值按剩余韧性占上限的60%/20%/5%计算。空槽仍可钓鱼，使用基础100韧性、3.75米/秒。

鱼线物品耐久与线韧性分开，不自动恢复。每竿成功、未提竿、鱼逃走、上岸或中断都按“没断线”结算一次：65%扣1，35%不扣；断线为95%扣1、5%扣3。每件鱼线独立保存耐久，耗尽后消失并卸下，只保留其他槽位装备，不自动装备备用鱼线。旧存档没有耐久字段的鱼线按对应满耐久迁移。装备中的物品必须先卸下放入仓库才能出售，剩余耐久不影响原定卖价。`clear` 保留装备槽物品；新存档两个槽位均为空。

抛竿前将本竿固定的两种损耗结果、鱼线ID与轮次写入 `storage.pendingCast`，与亮片扣量在同一笔保存中提交。抛竿成功后才等待结算，不提前扣物品耐久。结束时选择对应结果并清除记录；刷新/关闭页面/切换存档按已保存的“没断线”结果结算，不重新抽取。异常中断若未收到关闭事件，下次启动也恢复同一笔待结算记录。失败的结束写入会保留待保存状态并阻止新一竿和切档，恢复写入后继续；浏览器存储完全不可写时仍会提示，不能保证强制结束进程前尚未写入的数据。

`storage.equipment` 保存已装的两件物品，`lineWear` 为每件鱼线的物品耐久，`castSequence` 为结算编号。各存档互相隔离；装备ID与背包/仓库共用唯一编号，装卸移动原物品而非复制。`equipment-rules.js` 保存加成和损耗规则，战斗每竿使用独立数值快照，不修改全局鱼资料。关闭或切换界面不会重抽损耗；删除其他存档不会结束当前一竿。

三种鱼线共用“1级鱼线.png”，两种亮片分别使用“假饵1.png／假饵2.png”，渔轮使用“渔轮1.png”。仅处理这四张本次道具素材，保留原始文件，完整展示素材在 `fish-images/tackle/`，等比无损轻量缩略图在 `fish-images/thumbnails/tackle/`，最大512×384；复用原图片加载器与缓存，不批量处理旧鱼图片。素材工具须明确指定：`python scripts/build-tackle-images.py --source-dir 来源目录 --items line-1 lure-1 lure-2 reel-1`，只维护所列图片。

验证：`tests/equipment.test.js` 检查装卸、满仓更换、数值、每竿损耗、刷新恢复、失败回退、存档隔离与本次素材哈希；`tests/browser/refit.cjs` 检查真实界面、实际断线扣3、物品耗尽、收线韧性上限、禁止中途改装、刷新和切档只结算一次、旧存档迁移、图片及手机布局。截图和结果在 `.qa/refit/`。未增加 GitHub Actions。

仓库按钮下方新增半透明圆形商店入口。木质界面左上为 `starter's shop`，右上显示金币，商品按 3 列 × 2 行展示，数量从 1 开始，可加减或输入正整数，并显示总价。打开商店暂停游戏，不清空鱼堆；右下“返回湖边”或 Esc 关闭。

| 商品 | 买价 | 单个卖价 | 高×宽 | 品质 | 堆叠上限 |
|---|---:|---:|---|---|---:|
| 1号鱼线 | 2 | 1 | 1×1 | grey | 1 |
| 2号鱼线 | 10 | 5 | 1×1 | white | 1 |
| 3号鱼线 | 45 | 23 | 1×1 | white | 1 |
| 1号亮片 | 1 | 1 | 1×1 | white | 100 |
| 2号亮片 | 3 | 2 | 1×1 | light green | 100 |
| 1号渔轮-初学者 | 150 | 75 | 2×2 | turquoise | 1 |

从0.43.0起道具使用对应图片，鱼线和渔轮需在改装页装备后产生加成。购买先补满已解锁仓库的同种亮片堆叠，再按当前箱子、其余已解锁箱子的顺序寻找连续空格。整批全部放得下且金币足够才扣钱并交付，否则整批取消。购买、出售与抛竿消耗都必须成功保存后才生效。

道具可在背包和仓库之间移动，不旋转，不进入鱼堆，也不能与其他物品相互挤压覆盖。普通鱼覆盖普通鱼时仍可进入鱼堆。同种亮片拖到一起会合并至 100，超出的留在原处；目标堆已满则不移动。仓库出售模式双击亮片出售整堆，按每个售价先四舍五入，再乘数量（例如2号亮片99个出售198金币）；鱼的售价保持原样。

每次有效抛竿从背包格子中选择价格最高的可用亮片并消耗一个，数量为0时删除该堆，之后自动改用下一堆/低级亮片。无亮片时按地图基础概率。仓库内亮片不生效；管理员指定鱼种不消耗亮片。忙碌时重复按空格、朝陆地抛竿等无效操作不扣亮片。没钓到、断线、跑鱼也不退还本竿已消耗亮片；本竿选鱼已固定，中途挪动物品不改变结果。

概率由基础地图表派生，原表不修改。1号亮片将 grey/white 的实际概率分别乘 0.7/0.75，2号分别乘 0.56/0.6；减少的概率只按其他品质原有比例分配，同品质鱼种比例保持不变。当前地图汇总：

| 亮片 | grey | white | 其他品质合计 |
|---|---:|---:|---:|
| 无 | 22% | 39% | 39% |
| 1号 | 15.4% | 29.25% | 55.35% |
| 2号 | 12.32% | 23.4% | 64.28% |

`item-data.js` 独立保存六种商品，不加入鱼种配置、随机鱼池或图鉴。存档保留原物品结构，只有可堆叠亮片增加 `quantity`，范围1–100。物品、金币、数量仍归属当前独立存档，刷新和切换可恢复，`clear` 也清除背包道具但保留仓库道具。

验证：`tests/shop.test.js` 检查购买、连续空间、堆叠、碰撞、整堆出售、概率、消耗、失败回退与存档隔离；`tests/browser/shop.cjs` 检查木质商店、真实购买/转移/合并/抛竿、数量与自动切换、管理员旁路、空间和金币不足、保存失败、刷新及手机布局，输出位于 `.qa/shop/`。复用旧鱼缩略图，不生成或处理旧素材，不增加 GitHub Actions。

## 三个独立存档（0.41.0）

设置中的“新存档”会先询问，再创建并进入完全全新的游戏。已有进度保留为“存档 1”；每个存档各自保存背包、鱼堆、仓库、箱子解锁、金币与图鉴，最多同时保留 3 个。新存档金币为 0、物品为空、图鉴全锁，仅首箱免费。存档在本浏览器内保存，刷新后继续最近使用的存档。

“选择存档”显示三个编号、金币、鱼的数量和图鉴解锁数，可选择切换或删除。切换前会保存当前进度，再重新进入场景；新建和切换都会结束本轮钓鱼，管理员选鱼等临时状态也会重置。删除需要再次确认，当前使用中的存档不能删除，须先切换，因此至少保留 1 个存档。删除后空出的编号可用于新建，旧进度不会复活。`clear` 与 `rich` 只作用于当前存档。

存档集中保存在 `fisher-realm-save-slots-v1`（`version,revision,activeId,slots`），每项含独立的 `data.inventory` 和 `data.discoveries`。旧的物品/图鉴键自动迁入存档 1，仅在整份新存档写入成功后清理旧键；保存失败不切换、不新建、不删除，并保留待保存的钓获和图鉴。切换后的旧页面不能把旧模型写入新存档；检测到其他窗口已更新存档时拒绝旧页面覆盖。每个存档内部仍跨地图共用资料。

验证：`tests/save-slots.test.js` 覆盖迁移、存档隔离、上限、删除、保存失败和旧窗口保护；`tests/browser/save-slots.cjs` 覆盖实际新建/切换/删除、暂停与刷新、仓库和图鉴恢复、保存失败及手机尺寸，截图和结果在 `.qa/save-slots/`。

## 仓库与金币（0.40.0）

右上角设置下方的半透明圆形箱子按钮打开仓库，左上角 × 或 Esc 关闭。每次打开会直接丢弃鱼堆全部鱼，不获得金币，保留图鉴记录；切换箱子不再次清理。仓库打开时暂停游戏。

左侧为共用的 5×3 背包，右侧为当前箱子的 10×10 格子。可双向拖动，或先点鱼再点目标格，不支持旋转；在仓库界面占位冲突或越界时拒绝移动，鱼留在原处。普通背包界面的覆盖入鱼堆规则保留。第一个箱子免费，另九个可任意顺序解锁，每个固定 1000 金币。

右下角“出售”开启后，双击右侧仓库物品出售；鱼按 `fish-data.js` 中 `sellPrice` 支付，道具按商店规则支付，出售后物品同时消失；悬停可查看售价。再次点击或关闭仓库退出出售。除商店位于右上角外，其他界面左上角显示金币，初始为 0。

每个存档的物品资料保留 `version:1,items` 和 `storage:{version:1,coins,activeBox,boxes}` 结构；0.40.0 曾保存于 `fisher-realm-inventory-v1`，从 0.41.0 起由三存档管理器存入当前存档的 `data.inventory`。旧存档直接迁移，升级本身不清空鱼堆。金币、物品转移、出售、解锁与清理在同一次 `localStorage.setItem` 中整体保存，失败时取消操作。捕获新鱼若暂时无法保存会留在当前内存并提示，在重新聚焦、关闭弹窗或离开页面时重试。存档为本浏览器所有地图共用，并非 GitHub 或跨设备云存档。

验证：`node --test tests/storage.test.js` 检查迁移、交易和回退；`tests/browser/warehouse.cjs` 检查拖动、暂停、解锁、出售、指令、刷新及不同窗口尺寸，报告和截图位于 `.qa/warehouse/`。本功能未增加 GitHub Actions。

## Windows 一键试玩

1. 如收到 ZIP，请先完整解压到普通文件夹。
2. 双击 **启动游戏.cmd**，浏览器会自动打开游戏。
3. 游玩期间保留启动窗口，关闭窗口即停止服务器。

无需安装 Node.js、Python 或任何开发工具；启动器使用 Windows 自带的 PowerShell。全部 3D 依赖已保存在 vendor，运行时不需要联网。请使用支持 WebGL 2 的 Chrome 或 Edge，保持浏览器图形加速开启。不要直接双击 index.html。

启动器默认使用 http://127.0.0.1:5173/，端口被占用时自动尝试 5174–5183，实际地址见启动窗口。服务只监听本机。

抛竿入水后，鱼所在的水面上方会显示与玩家的水平距离，保留一位小数；文字随鱼移动和距离实时更新，钓获或失败后隐藏。

## 鱼种图鉴

美洲鳗鲡：turquoise（#40e0d0），高1格宽5格，不旋转；每0.38秒扣3点线韧性，挣扎速度8米/秒、耐力56，每轮按左右横向朝前30°–60°交替挣扎4、4、4秒，之后休息4秒，无额外停顿或特殊属性。当前20种鱼等概率，名单及数量以自动帮助/图鉴为准。

图鉴保存失败会保留待保存状态，在再次钓获（含同种鱼）、关闭弹窗、返回窗口或离开页面时重试；持续失败只提示一次，写入恢复成功后停止重复保存。解锁进度及物品存档格式保持不变，损坏物品存档中的非法鱼名会被过滤。

弹窗暂停期间保留静止的3D背景，轻量帧调度保持响应窗口变化；尺寸变化时补画一帧，关闭弹窗后恢复原25帧目标及剩余钓鱼过程。暂停不参与低帧率采样。文字、样式、状态属性仅在变化时写入，同一鱼方向复用岸边计算。本轮不改变后台计时策略或自动画质恢复策略。

从右上角齿轮设置打开，采用与背包一致的深绿色弹窗。未钓获的鱼只显示锁，不显示名称、图片、参数或颜色，不可展开，也不请求对应鱼图。成功钓获一次后永久解锁，列表自动读取统一鱼种配置，显示图片、名称、耐力、游戏挣扎速度和完整力量（点数/扣线间隔），以及“钓获提示色”和“背包底色”两个独立色块；不常驻显示颜色名称或色值，色块加边框便于辨认。

点击已解锁鱼种原位展开，一次最多展开一条；详情显示每轮休息、背包高宽、不旋转、普通随机遇鱼概率、特殊属性、各段挣扎时长及换边停顿。角度沿用游戏规则：从正左/正右朝本轮正前方转，0°横向、90°正前方。当前版本不增加排序、成就或真实鱼类科普。

每次打开都会清空搜索、折叠全部鱼种并回到列表顶部。搜索只匹配已解锁鱼种的名称，隐藏锁定项，保留配置中的鱼种顺序；搜索结果数量不会改变遇鱼概率。“？”帮助中的自动鱼种资料按之前约定继续保留。新增或调整配置后，图鉴、帮助与实际游戏同步，不维护第二份鱼种数据，新鱼默认上锁。

解锁历史按稳定鱼种 ID 保存，0.41.0 起位于当前存档的 `data.discoveries`，自动迁移原来的 `fisher-realm-discoveries-v1`。`clear` 清空鱼堆、背包和金币，不重置图鉴、仓库物品或箱子解锁状态。仅真正成功钓获才解锁，抛竿、咬钩、提竿、失败或管理员选鱼均不会解锁。旧版本没有历史钓获账本，升级时会根据仍保存在背包或鱼堆中的鱼补解锁，已经清除的鱼无法追溯。解锁记录写入失败会提示，当前游戏仍可查看。

列表只下载轻量缩略图；展开某条鱼后才加载对应原图，加载期间保留缩略图。没有配置图片显示“暂无图片”，配置图片请求失败则分别显示缩略图或原图失败提示，重新打开可重试。复用背包的共享下载缓存和并发限制，保持比例、原色、透明度。

任何钓鱼阶段均可打开图鉴。复用游戏时钟暂停咬钩、提竿窗口、挣扎/换边停顿/休息、资源变化、水波、收竿和钓获提示，并暂停正在播放的钓鱼音效；关闭后继续剩余过程。打开时释放收线，关闭后须重新按住左键。搜索输入、点击及 Esc 不会触发钓鱼。图鉴、背包、帮助和选鱼弹窗互斥并统一暂停，只有最后一个弹窗关闭才恢复游戏。

`tests/browser/fish-guide.cjs` 使用已有 Playwright/Chrome 验证界面、图片失败及恢复、新增配置、屏幕适配和各阶段暂停。阶段测试仅在测试浏览器中替换时钟输入、固定随机数和模拟媒体设备；钓获用例使用临时弱鱼参数加速，正式配置和钓鱼算法不变。运行方式与其他浏览器脚本相同，指定 `PLAYWRIGHT_MODULE`（可选 `CHROME_PATH`）后用 Node 执行，无新增游戏依赖或 GitHub Actions。

`tests/browser/fish-guide-unlocks.cjs` 专门验证新玩家全锁、隐藏名称和参数、不请求锁定鱼图、名称搜索不泄露、旧存档补解锁、真正钓获解锁、管理员选择不解锁、clear 后保留以及刷新恢复。原图鉴浏览器用例预置完整解锁历史，继续保护已解锁界面的原有交互。

## 新增普通鱼种（统一配置）

`fish-data.js` 是鱼种参数的唯一数据来源。普通鱼使用现有 1～5 段左右挣扎及可选换边停顿机制，只需向 `FISH_DATA` 末尾追加一条记录，无需修改钓鱼引擎、背包规则或管理员界面。

每条记录包含：稳定英文 `id`、唯一中文 `name`、力量 `strength.amount/interval`、休息 `restDuration`、速度 `speed`、耐力 `stamina`、横向角度 `struggle.minAngle/maxAngle`、时长数组 `struggle.durations`、可选 `struggle.switchPause`、特殊说明 `specials`、钓获文字色 `catchColor`，以及背包 `inventory.w/h/color/image`。尺寸 w 是宽、h 是高；图片路径相对 `fish-images/`，暂无图片写 `null`。钓获文字色与背包底色分别填写，不能合并。旧罗非鱼的两段时长字段保留兼容。

保持已有名称、ID 和顺序不变，鱼仍等概率出现；名称是现有存档识别依据。新增项放在末尾。配置导入时检查重复名称/ID、正数参数、0～90°横向角度、1～5 段正时长和 5×3 背包边界。

新增或调参后运行 `npm test`。通用测试自动遍历全部鱼种；原有专属测试和 V0.25.1 基线快照用于保护旧鱼属性，不需要因为新增鱼种而改写快照。`tests/fish-data.test.js` 在临时目录验证只改配置即可接入新鱼，正式目录中不添加测试鱼。全新运动机制应另行讨论，不用普通配置冒充。

本次重构不调整版本/缓存标识管理、不增加 Actions、不修改 Pages 部署。发布时的缓存刷新仍沿用现有流程，另行处理；下方历史鱼种说明是静态说明，统一配置为实际参数依据。图片制作、文档更新和正式发布与参数录入分别安排。

## 已确认的钓鱼规则

- 空格抛出后 6–13 秒随机咬钩，鱼线上下浮动；从咬钩开始算，1.45 秒内按任意键可提竿。超时则鱼脱钩，恢复初始状态。
- 拉鱼时镜头自动跟随鱼的位置；鱼竿保持独立的世界朝向，必须由玩家移动鼠标左右转动。鱼不显示任何模型，只保留逻辑位置，以鱼线末端和水波提示拉鱼位置。
- 收线基准为 3.75 米/秒。鱼竿与鱼的水平夹角 ≤3° 为 120%（4.5 米/秒），>3° 至 30° 为 100%（3.75 米/秒），>30° 至 90° 为 75%（2.8125 米/秒），>90° 为 20%（0.75 米/秒）。松开左键立即停止收线。
- 鱼距钓位 1.25 米时判定钓获。以此刻为 0 秒：0.3 秒后左下角显示浅灰色“罗非鱼已被钓”，0.8 秒后可再次抛竿，4.5 秒开始淡出，淡出动画 0.6 秒。
- 快捷键在咬钩窗口内优先作为提竿键，避免按 F 或 R 提竿时同时触发其他操作。设置面板与说明弹窗内仍以界面操作为准；切走窗口或打开面板会松开收线，避免卡住左键。
- 成功后自动抬竿，空鱼线沿带有侧向摆动的弧线荡向玩家，动作在 0.8 秒内完成；不显示鱼模型。
- 水波分为四种：抛竿入水、开始提竿、挣扎移动或收线时产生的小水波、成功离水时的大水波。临岸效果留在实际水面；鱼休息且没有收线时不再新增小水波，已有水波自然消散。
- 水波使用固定大小的对象池，避免连续抛竿和收线导致模型数量持续增加。
- 本版距离按鱼到固定钓位的水平距离计算。

渲染以约 25 FPS 为目标并限帧；植被使用实例化批量绘制，静态树荫预先生成。精细模式保留更清晰的倒影，流畅模式降低分辨率和倒影更新频率，持续低帧率时自动下调渲染分辨率。实际表现取决于设备、浏览器和窗口分辨率。

## 线韧性与罗非鱼属性

每次抛竿线韧性从 100 开始，上限 100。仅在鱼挣扎且按住左键收线时，每 0.2 秒扣除 3 点。最后一次扣除后 0.95 秒首次恢复 2.5 点，之后每 0.1 秒恢复 2.5 点，最高 100。松开或鱼休息时不会扣线韧性。快速松开再按下不会清空资源计时的零头。

鱼线及韧性条同步变色：大于 60 为原色，≤60 黄，≤20 橙，≤5 红。归零断线失败；鱼超过 50 米、或进入距玩家大于 10 米的陆地也会失败。10 米内允许经过岸地，以便完成收竿。

罗非鱼：力量每 0.2 秒扣 3 点，挣扎速度 4.2 米/秒，初始耐力 44，每轮休息 3.3 秒，无特殊属性。提竿立即开始：每轮以当时玩家指向鱼的方向作为固定基准，随机先左或右，以横向为起点朝本轮正前方转 32°–42°跑 3.9 秒，再换边，从另一侧横向朝正前方重新随机转 32°–42°跑 3.4 秒，休息 3.3 秒后开启下一轮并重新确定基准。移动与收线牵引同时作用。

只有挣扎中收线才削减鱼耐力，比较的是鱼当前游动方向与竿方向：≤25° 每 0.25 秒减 3，>25° 至 75° 每 0.25 秒减 1，>75° 每 0.2 秒减 0.5。鱼耐力不恢复，归零立即永久休息，仍能被收回。此角度独立于决定收线效率的“竿与鱼位置方向”夹角。

## 版本与资源缓存（第二阶段）

当前版本只以 `package.json` 的 `version` 为准，页面及调试状态自动读取。发布时执行 `npm version <新版本> --no-git-tag-version`，自动同步 npm 锁文件；不再修改各程序中的查询标识。每次实际发布内容都必须使用新版本号，同一版本的资源视为不可变。

页面先读取带唯一检查参数的 `package.json`（禁止浏览器缓存），再安装原生 import map，为整个模块依赖图和样式生成同一 `?v=版本` 地址。图片、预加载图片和音效也使用这个版本。启动器本身每次以新的启动地址读取，不增加 Service Worker、构建框架或运行依赖。模块清单位于 `package.json` 的 `fisherRealm.modules`；新增普通鱼无需变更清单，新增程序模块时才需登记，测试检查遗漏。

此机制适用于 GitHub Pages 子目录、本地 Node 启动和双击启动。初次切换仍可能需要打开新发布链接或刷新旧 HTML；新版模块检测到旧入口时会提示重新加载，并使用新页面地址获取入口；已加载的旧标签页不会强行刷新、打断钓鱼，下次刷新/重新打开才加载新版本。版本清单失败时显示可重试错误，不静默混用旧版本。它不承诺跨发布的长期历史资源托管或持续监测已打开页面的更新。帮助窗口使用同一份配置，新增鱼和调整参数后随新版本同步更新。

实现依据：[浏览器原生 import map 的相对 URL 映射](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script/type/importmap)。

浏览器缓存回归：使用已有 Playwright 安装，执行 `node tests/browser/release-cache.cjs`（可通过 `PLAYWRIGHT_MODULE` 和 `CHROME_PATH` 指定本机依赖与 Chrome）。测试使用临时 HTTP 服务及独立浏览器上下文，模拟 Pages 子目录、长效旧缓存、新版配置变化、资源失败、重试和旧 HTML 恢复，不修改游戏数据或线上站点。


## 帮助文字自动读取配置（第三阶段）

`fish-help.js` 从 `FISH_DATA` 自动生成帮助窗口中的名单、数量、等概率、力量/扣韧间隔、休息、速度、耐力、横向角度、各段时长、换边停顿、特殊说明、背包高宽和两类颜色。鱼种资料按鱼名折叠显示；每次打开帮助重新生成，重复打开不叠加条目。无须在 HTML 中再次填写鱼名和数值。

罗非鱼的旧时长字段仍兼容；单段鱼明确说明不在轮内换边，停顿仅出现在实际换边处。缺省钓获颜色与规则共用 `DEFAULT_CATCH_COLOR`，保留原来的浅灰色。既有玩法参数没有调整。发布仍需按第二阶段流程使用新版本号；已经打开的游戏不会自动换成另一套参数。下方/上方历史 README 鱼种介绍不会作为游戏帮助的数据源。

验证：`npm test`；浏览器帮助专项 `node tests/browser/fish-help.cjs`（与缓存回归一样，使用已有 Playwright/Chrome，可设置 `PLAYWRIGHT_MODULE`、`CHROME_PATH`）。浏览器用临时响应模拟新增第20种鱼及旧鱼调参，正式配置不加入测试鱼。


## 背包图片加载修复

全部鱼种优先使用独立的512×384以内等比缩略图，原图路径和鱼种配置保留。运行 `python scripts/build-inventory-thumbnails.py` 可从配置批量生成，开发时需 Pillow 和 Node，游戏无新增运行依赖。新鱼没有缩略图时自动回退到原图。加载器按 URL 共享下载与成功缓存，最多4个并发，重绘/重复鱼卡复用结果；慢请求等待上限120秒，每个来源最多尝试2次，原图失败后显示错误，重新打开可以重试。移除仅针对黄鲶和弓鳍鱼的预加载，全部鱼种按相同方式加载。
