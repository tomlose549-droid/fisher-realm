# 单地图接口与后续扩图约定

本版只整理现有 `summer-pond`，没有第二张正式地图、地图菜单、鱼种地图字段或勾选工具。

## 文件职责

- `maps/summer-pond.js`：现有地图的稳定 ID、出生钓位/朝向、水位、岸线参数、环境和画质数据；岸线点与水域判定使用同一组参数。
- `pond-scene.js`：现有池塘的具体几何/材质和环境效果，以及统一场景接口。保留原路径，避免无必要的大量搬动。
- `map-registry.js`：地图定义和延迟加载入口、只读地图上下文、当前地图鱼池。未知地图报错，不能默认为所有鱼。
- `map-runtime.js`：创建地图实例并提供公共接口，不创建背包/图鉴、不写存档、不注册全局输入、不创建额外渲染循环。
- `idle-rod.js`：独立于地图的玩家鱼竿，拥有自己的图形资源。
- `scene-resources.js`：释放作用域独占的几何、材质、纹理、实例缓冲、阴影及渲染目标，重复释放无副作用。显式 `sharedResources` 由外层管理，不随地图销毁。

## 地图实例接口

`createMapRuntime({scene,camera,renderer,id,sharedResources})` 异步加载注册的构建模块；构建模块导出 `createMap`，返回以下接口：

| 接口 | 职责 |
| --- | --- |
| `context` | 稳定 ID、名称、钓位/朝向、实际水位、水域函数、当前鱼池及地图提示文字 |
| `playerPosition` | 以米为单位的钓位坐标 |
| `update(elapsed)` | 更新本图环境动画；时间由公共游戏时钟传入，暂停不继续动画 |
| `setQuality(fine)` | 设置本图的画质资源，例如水面反射分辨率 |
| `renderReflection({frame,fine,force,before,after})` | 本图决定反射时机；通过钩子隐藏/恢复玩家物件，并在失败时恢复渲染目标和水面可见性 |
| `getDiagnostics()` | 提供场景数量、画质资源及释放状态，便于验收 |
| `dispose()` | 清理本图独占资源、移除地图根节点并还原本图设置的环境；不销毁公共渲染器、相机或存档 |

场景构建失败会清理已创建的根节点和资源、还原环境。只有一个正式地图实例处于使用状态。后续地图切换控制器负责空闲检查、加载状态和失败恢复，本版不提供切换菜单。以后新增地图的模块必须加入 `package.json` 的统一版本清单；清单登记不等于提前下载所有地图，实际构建模块使用动态 import。

池塘的岸线点、地形高度和水域辅助函数均可接收同一份 `water` 配置；构建器使用传入的 `config.water`，不会混用默认池塘参数。场景构建器不设置公共相机；由地图工厂在构建成功后统一应用钓位和朝向。构建失败保留原相机位置与朝向，并还原渲染器曝光及阴影更新标志。

## 钓鱼与全局数据

`createFishing` 接收 `mapContext`，不再直接引用池塘边界；漂、距离文字和水波按水位计算。`FishingSession` 接收可选 `fishPool`，默认保持原全局鱼池，现有池塘仍包含全部已配置鱼种。开发用指定选鱼保留原全局行为，地图名单勾选功能后续再确认和开发。

以后切换时，应先停止输入并确认当前钓鱼空闲；释放旧的钓鱼展示实例和地图，再用新上下文创建钓鱼展示实例。全局输入监听只注册一次并指向当前实例；背包、鱼堆、图鉴和游戏时钟不因换图重建。玩家鱼竿可以跨地图复用，只有销毁整个游戏时才调用其 `dispose`。

背包与图鉴继续使用原有全局存档键，保存格式不变。地图进度以后另存，旧存档默认进入 `summer-pond`。地图鱼池只能影响随机遇鱼，不能用于过滤/删除背包和图鉴中的全局鱼种。

将来鱼数据中的地图归属建议使用稳定地图 ID 数组；未配置默认属于现有地图，不能自动属于所有未来地图。勾选作为开发配置工具，结果写入鱼数据并经提交/发布生效，不把浏览器本地勾选当作修改 GitHub 源码。本版没有写入任何鱼种归属字段，也没有改鱼参数或处理图片。

## 验收

`tests/map-runtime.test.js` 覆盖现有岸线兼容、只读上下文、鱼池注入和资源所有权。`tests/browser/map-runtime.cjs` 使用独立测试场景验证反复创建/释放后 GPU 数量不累计、共享相机/物件保留、创建/反射失败恢复、水位和鱼池注入、钓获起竿动画，以及全局存档不受影响。它不会注册第二张正式地图。

公共架构改动需要检查现有池塘、钓鱼、暂停、存档和版本缓存。后续只新增普通鱼时继续使用指定鱼种验收，不重新处理旧鱼数据或图片。

## 当前地图的遇鱼概率

`maps/summer-pond-fish.js` 保存当前地图每种鱼的绝对百分比，合计必须100%。`fish-encounters.js` 用整数基点校验、计算品质合计并编译抽取区间；品质取自鱼资料的独立 `quality`，与显示颜色无关。地图上下文同时提供配套的 `fishPool` 和 `encounters`，钓鱼、帮助及图鉴使用同一张概率表。背包与图鉴存档仍是全局数据，不随地图鱼池过滤。

以后新增地图应提供自己的完整概率表；当前没有新增地图、切换菜单或鱼种地图勾选工具。新增鱼时先向用户确认概率及调整来源，缺项、重复鱼、未知鱼、无效品质或总量不等于100%都会阻止使用，不能偷偷平均分配或归一化。`realm owner` 仍可指定全局鱼种，成功10条后恢复当前地图概率。
