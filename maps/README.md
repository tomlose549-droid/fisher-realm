# 地图接口与扩图约定

当前有四张3D地图：`summer-pond`（美国奥基乔比湖）、`amazon-confluence`（亚马逊 · 河道交汇区）、`amazon-flooded-forest`（亚马逊 · 沉木水草区）与 `sac-actun`（墨西哥·萨克阿克通水下洞穴系统）。世界地图支持独立选择，鱼种地图字段和勾选工具仍未开发。

## 文件职责

- `maps/summer-pond.js`：现有地图的稳定 ID、出生钓位/朝向、水位、岸线参数、环境和画质数据；岸线点与水域判定使用同一组参数。
- `pond-scene.js`：现有池塘的具体几何/材质和环境效果，以及统一场景接口。保留原路径，避免无必要的大量搬动。
- `map-registry.js`：地图定义和延迟加载入口、只读地图上下文、当前地图鱼池。未知地图报错，不能默认为所有鱼。
- `map-runtime.js`：创建地图实例并提供公共接口，不创建背包/图鉴、不写存档、不注册全局输入、不创建额外渲染循环。
- `map-session.js`：独占当前地图与钓鱼展示，切换时先释放旧实例；创建失败清理已完成的部分。只携带当前页管理员选鱼剩余次数，不拥有全局存档。
- `maps/amazon-confluence.js`：亚马逊钓位、河道及平台水域边界、环境和画质配置。
- `maps/amazon-confluence-fish.js`：亚马逊独立概率表；63种鱼按显式绝对概率抽取（最小0.001%，合计100%），具体鱼种概率以该配置为准。
- `amazon-scene.js`：米制3D雨林、树根藤蔓、木平台及钓具，实例化植被和限频河面反射；纹理由程序生成，不用参考图片充当3D背景。
- `idle-rod.js`：独立于地图的玩家鱼竿，拥有自己的图形资源。
- `scene-resources.js`：释放作用域独占的几何、材质、纹理、实例缓冲、阴影及渲染目标，重复释放无副作用。显式 `sharedResources` 由外层管理，不随地图销毁。

## 地图实例接口

`createMapRuntime({scene,camera,renderer,id,sharedResources})` 异步加载注册的构建模块；构建模块导出 `createMap`，返回以下接口：

| 接口 | 职责 |
| --- | --- |
| `context` | 稳定 ID、名称、钓位/朝向、实际水位、水域函数、当前鱼池及地图提示文字 |
| `playerPosition` | 以米为单位的钓位坐标 |
| `update(elapsed)` | 更新本图环境动画；时间由公共游戏时钟传入，暂停不继续动画 |
| `setQuality(fine)` | 设置本图的画质资源，例如水面反射分辨率 |
| `renderReflection({frame,fine,force,before,after})` | 本图决定反射时机；通过钩子隐藏/恢复玩家物件，并在失败时恢复渲染目标和水面可见性 |
| `getDiagnostics()` | 提供场景数量、画质资源及释放状态，便于验收 |
| `dispose()` | 清理本图独占资源、移除地图根节点并还原本图设置的环境；不销毁公共渲染器、相机或存档 |

场景构建失败会清理已创建的根节点和资源、还原环境。只有一个正式地图实例处于使用状态。世界地图的忙碌状态阻止重复进入；`map-session.js` 先释放旧图再创建所选地图，失败留在世界界面，允许重试或选择另一钓点。以后新增地图的模块必须加入 `package.json` 的统一版本清单；清单登记不等于提前下载所有地图，实际构建模块使用动态 import。

池塘的岸线点、地形高度和水域辅助函数均可接收同一份 `water` 配置；构建器使用传入的 `config.water`，不会混用默认池塘参数。场景构建器不设置公共相机；由地图工厂在构建成功后统一应用钓位和朝向。构建失败保留原相机位置与朝向，并还原渲染器曝光及阴影更新标志。

## 钓鱼与全局数据

`createFishing` 接收 `mapContext`，不再直接引用池塘边界；漂、距离文字和水波按水位计算。`FishingSession` 接收可选 `fishPool`，默认保持原全局鱼池，现有池塘保留原已配置鱼种，新亚马逊鱼在池塘的概率为0%。开发用指定选鱼保留原全局行为，地图名单勾选功能后续再确认和开发。

切换前先停止输入，按当前竿的固定规则中断并成功保存，再释放旧的钓鱼展示实例和地图；进入时用新上下文创建钓鱼展示实例。全局输入监听只注册一次并指向当前实例；背包、鱼堆、图鉴和游戏时钟不因换图重建。玩家鱼竿可以跨地图复用，只有销毁整个游戏时才调用其 `dispose`。

背包与图鉴在每个独立存档内跨地图共用，通过 `save-slots.js` 的适配器读写当前存档，地图不得直接访问或修改存档键。最多 3 个存档互不混用。地图进度以后另存，所有存档打开时先进入世界地图，再选择钓点。地图鱼池只能影响随机遇鱼，不能用于过滤/删除背包和图鉴中的全局鱼种。

将来鱼数据中的地图归属建议使用稳定地图 ID 数组；未配置默认属于现有地图，不能自动属于所有未来地图。勾选作为开发配置工具，结果写入鱼数据并经提交/发布生效，不把浏览器本地勾选当作修改 GitHub 源码。当前未写入鱼种归属字段；各地图的独立概率表决定普通遇鱼，新增地图不改旧鱼参数或图片。

## 验收

`tests/map-runtime.test.js` 覆盖现有岸线兼容、只读上下文、鱼池注入和资源所有权。`tests/browser/map-runtime.cjs` 使用独立测试场景验证反复创建/释放后 GPU 数量不累计、共享相机/物件保留、创建/反射失败恢复、水位和鱼池注入、钓获起竿动画，以及全局存档不受影响。它在独立测试场景检查地图接口；实际游戏中只允许一个地图实例。

公共架构改动需要检查现有池塘、钓鱼、暂停、存档和版本缓存。后续只新增普通鱼时继续使用指定鱼种验收，不重新处理旧鱼数据或图片。

## 当前地图的遇鱼概率

`maps/summer-pond-fish.js` 保存当前地图每种鱼的绝对百分比，合计必须100%。`fish-encounters.js` 用整数基点校验、计算品质合计并编译抽取区间；品质取自鱼资料的独立 `quality`，与显示颜色无关。地图上下文同时提供配套的 `fishPool` 和 `encounters`，钓鱼、帮助及图鉴使用同一张概率表。背包与图鉴存档仍是全局数据，不随地图鱼池过滤。

以后新增地图应提供自己的完整概率表；当前已有四张地图，鱼种地图勾选工具仍待后续授权。新增鱼时先向用户确认概率及调整来源，缺项、重复鱼、未知鱼、无效品质或总量不等于100%都会阻止使用，不能偷偷平均分配或归一化。`realm owner` 仍可指定全局鱼种，成功10条后恢复当前地图概率。

## 世界地图入口

`world-map-data.js` 保存世界图片、各钓点的归一化坐标、稳定地图ID和预览素材；`world-map.js` 负责图片拖动/缩放、首次点击预览与再次点击进入。预览是现有场景截图，不创建额外渲染器。初次打开及刷新都停在世界地图，首次进入或打开仓库才延迟加载 `main.js`。

普通仓库先暂停并按既有规则中断本轮钓鱼，成功保存进度与清空鱼堆后才返回世界地图并打开仓库。任一步失败不离开钓点、不清鱼堆；关闭仓库留在世界地图。任务提交仓库仍沿用独立流程，不清鱼堆。回到世界地图后释放场景与钓鱼展示，世界界面不保留3D地图实例，也不更新或渲染3D。`tests/browser/world-map.cjs` 覆盖入口、两次点击、拖动/双指缩放、反复往返、断存储保护和耐久只结算一次。


## 亚马逊场景与验收

光点的地理锚点取玛瑙斯附近内格罗河/索利芒斯河交汇区域，约南纬3.14°、西经59.91°；插画地图上的位置按陆地轮廓校准，并非经纬度等距投影。参考资料：https://sigep.eco.br/sitio054/Poligonal_area_protecao_Sitio054_Ponta_das_Lajes_e_o_Encontro_das_Aguas_AM.pdf 。场景外观按用户参考图制作林中河道和木平台，而非等比例复原真实交汇区。预览为实际运行场景截图，首次点击不加载任一3D地图模块。

亚马逊使用63种鱼的显式权重表，位于 `maps/amazon-confluence-fish.js`；品质总计为grey 22%、white 24%、light green 16%、green 12%、turquoise 10%、blue 7%、indigo 4%、dark purple 2.5%、violet 1.3%、pink 0.7%、yellow 0.3%、orange 0.15%、red 0.04%、dark red 0.01%。概率保留0.001%精度，总计100%，禁止自动均分或归一化。入场费由 `map-entry.js` 单处维护，每次成功进入28金币，旧湖泊0金币；新存档可先在免费湖泊获取金币。售价从全局鱼资料读取，背包、仓库、图鉴和各地图共用。

雨林使用实例化枝叶、根系和植被、一次烘焙静态阴影、受限分辨率及频率的河面反射，主循环仍以25帧为目标并保留自适应分辨率。反复离开时释放程序纹理、网格、阴影和反射目标；公共鱼竿、渲染器和相机保留。失败创建不得把半成品留在场景或污染旧环境。

`tests/amazon.test.js` 覆盖专属鱼池、河道/平台、亮片扣量与缓存隔离、全局管理员名单及单地图会话。`tests/browser/amazon.cjs` 通过真实操作检查亚马逊鱼钓获、入包、跨地图图鉴/概率、管理员指定鱼、连续切换的GPU基线、构建失败后重试、刷新与仓库打开不创建地图。


亚马逊右转方向在原河道尽头接入宽203米的大水域，过渡区z=36–96米，延伸至z=230米。水面、两岸及抛竿/鱼上岸判定统一读取 `water.basin` 和 `riverBank`，平台、初始视角及前方河道保留。新增水面与原河道共用一个网格、材质和反射目标；远岸采用较少枝叶并并入原有实例批次。

亚马逊河道已按原宽度1.5倍加宽至31.5–46.5米，基础半宽与起伏幅度一起缩放。`riverBankOffset` 将原先固定的景物坐标关联到当前岸线；平台和钓具作为整体平移，玩家与平台水域排除范围同步移动，不拉伸模型。两岸地形、植被、水草和水域判定共用新岸线参数，避免改宽度后景物落在水中或钓位脱离岸边。

## 亚马逊 · 沉木水草区

`amazon-flooded-forest` 每次成功入场43金币，独立自然岸边第一人称钓位。配置与鱼池在maps/amazon-flooded-forest*.js，独立渲染模块flooded-forest-scene.js按需加载；原地图不加载此渲染模块。普通遇鱼使用独立的63种显式绝对概率表（最小0.001%，总计100%），亮片按现有规则调整并消耗；管理员仍可指定全局鱼种。沉木、树根、水草只有景物网格，无碰撞箱或挂底，不改变鱼的水域判断；岸线仍正常限制抛竿和鱼上岸。单水面与单反射目标，植被实例化及限频反射，25帧目标。预览是实际场景截图。专项：tests/flooded-forest.test.js、tests/browser/flooded-forest.cjs。

沉木水草区对岸右侧连通开阔水湾：z36–92平滑展开，最宽146米、延伸至z210；水域判断和岸线/水面共用同一配置。5段浮木仅作景物，7簇水下草纹融入原水面材质，保持单水面、单反射目标；低细节远岸植被继续使用原实例化批次。

## 墨西哥·萨克阿克通水下洞穴系统

`sac-actun` 每次成功入场45金币，固定左侧岩岸第一人称钓位，按用户同名图片构建完整3D洞穴：侵蚀石灰岩岩壁、岩檐与钟乳石、中央古树及交织树根、顶部开口与藤蔓、清澈蓝绿水面、水下沉木和岩石、左侧钓具箱与灯笼。参考图仅作构图/外观依据，不当3D背景。地理锚点参考IUGS坐标20.2464°N、87.4642°W；插画光点按尤卡坦海岸校准，具体钓位景观以用户图为准。来源：https://iugs-geoheritage.org/geoheritage_sites/sac-actum-underwater-cave-system/ 。

`maps/sac-actun.js` 保存同一套岸线/岩岸边界及钓位参数；`maps/sac-actun-fish.js` 为独立洞穴鱼池：按用户确认的59种显式绝对概率抽取，总计100%、支持0.001%精度；未列出的9种鱼为0%，红尾鲶0.2%，罗非鱼7%；五种洞穴新鱼售价分别为120/168/33/32/1金币；`cenote-scene.js` 延迟加载，不修改全局相机或注册输入。树根、沉木、岩石仅为景物，无碰撞箱或挂底；只有外围岸线及左侧岩岸作为陆地。亮片照常消耗，并按现有品质/占格规则调整本图基础概率，0%鱼种始终不出现，管理员仍可选全局鱼种。背包/仓库/图鉴和存档仍跨地图共用。

目标25帧，使用实例化岩石、钟乳石、藤蔓、枝叶，单水面及单限频反射；透光采用少量柔边光束，水面透明混合显示实际水下几何，反射裁掉水下景物。全部纹理在本地生成，预览为运行时实拍截图；纹理、阴影和反射目标随地图离开释放。专项为tests/sac-actun.test.js、tests/browser/sac-actun.cjs。

## 任务解锁门槛

新存档与无shop新任务字段的旧存档仅显示美国奥基乔比湖。shop主线1解锁amazon-confluence，主线3解锁amazon-flooded-forest，支线2任务2解锁sac-actun；三者费用分别为28/43/45金币。world-map.js按当前存档隐藏未解锁光点/预览，main.js注入mapUnlocked供入场控制器检查，未解锁不得创建场景或扣入场费。解锁来自独立任务链永久领奖前缀，owner hack退回任务不撤销解锁。地图数据/场景/鱼池仍独立于这些存档门槛。
