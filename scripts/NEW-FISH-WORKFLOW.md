# 新增普通鱼的固定流程

本流程只改善开发工具和验收，不改变钓鱼规则，不增加 GitHub Actions。

1. **先核对基线。** 查看 `git status --short`、当前分支和 `git worktree list`，保护已有未提交工作。执行一次 `node scripts/git-network.cjs fetch`，比较 `HEAD` 与 `origin/main`；若只是合并提交不同，用 `git diff HEAD origin/main --stat` 确认文件差异，再基于最新主分支建立或更新工作分支。不要重置其他聊天正在使用的目录。同步失败先看错误；网络、认证、分支冲突分别处理，不能无休止重试。API 导入提交只作必要的备用方案，并核对 SHA。
2. **只加本次鱼种。** 用户照常用中文发属性，助手将 `scripts/fish-template.json` 复制到 `.qa/` 后填写（用户不必学习 JSON）。工具明确使用秒、米/秒，高在前、宽在后；检查漏填/格式/范围、重复标识/名称、颜色和占格，转换为待核对配置。遇到“每轮移动”等单位不明或未支持的特殊属性，先与用户讨论；不由工具猜测。输出核对后才追加 `fish-data.js`，复用现有机制。
3. **先检查素材。** 保留用户原图；已有可用透明图直接复用。白底图只做必要的一次背景处理。怀疑杂色时，先检查透明度，再在该鱼背包底色上观察，不能凭黑底预览反复抠图。下面的 `--inspect` 输出 alpha 范围和 alpha≥8 的可见包围框，辅助定位近透明留白；它不自动判断美术质量。
4. **默认配备缩略图。** 有图的新鱼必须同时提交轻量 WebP，背包/鱼堆/图鉴列表优先用缩略图，展开后才用大图。只增加本次新鱼的缩略图，不处理原有鱼图，包括顺带压缩、转换、修改或补建记录；旧图维护须用户另行要求。生成命令必须指定 `--fish`，素材验收只针对本次鱼。最大512×384，等比、原色、保留透明背景；只有留白影响展示时才使用裁剪选项。缺图就明确标记缺图，不能报告素材完成。
5. **只验收本次新鱼。** 用 `node scripts/check-new-fish.cjs ID或名称` 一次完成依赖预检、指定鱼种的素材检查、规则及浏览器专项；不再调用全量 `tests/*.test.js`，不重查旧鱼参数或图片。规则脚本 `scripts/check-fish-rules.cjs` 只验证指定鱼的配置接入、随机/指定选鱼、速度/角度、每段挣扎/换边停顿/休息、力量扣韧、钓获颜色、占格/溢出/保存与图鉴解锁。仍须将本次配置与用户要求核对，不能只用配置自检替代。失败立即停止，输出 `.qa/new-fish/ID-acceptance.json`（scope 为 selected-fish，包含本次配置、资源指纹及阶段结果/耗时/错误），部分通过不算完成。浏览器只给本次鱼设置独立存档和解锁，覆盖选鱼/帮助、未钓获锁定、背包/鱼堆缩略图、图鉴色块/按需大图及刷新保存；先滚动再检查实际 URL，不接受悄悄回退大图。仅读取名单以核对数量/身份，不检查其他鱼的参数/图片。公共机制改变、故障涉及公共机制或用户另行要求时，才安排相关回归；历史完整测试保留供该用途使用。
6. **一次完成核对。** 核实实际参数符合用户要求、素材完整、只改本次范围、测试通过，创建独立 PR。记录基线、执行命令和结果，供审查复用。得到用户批准后才合并上线。仅开发工具/文档变更无需提升游戏版本；运行时配置/素材变更仍遵守现有版本管理。

## 命令示例

从项目根目录执行，ID 或名称均可，`--fish` 可重复指定多个鱼种：

```powershell
node scripts/prepare-fish.cjs .qa/new-fish-input.json --output .qa/new-fish-config.json
# 核对生成配置、追加名单并准备本次鱼的展示素材后：
python scripts/build-inventory-thumbnails.py --fish NEW_FISH_ID --inspect
python scripts/build-inventory-thumbnails.py --fish NEW_FISH_ID --crop-transparent
node scripts/check-new-fish.cjs NEW_FISH_ID
```

生成命令不带 `--fish` 会直接报错，避免误处理原有鱼。`--check`、`--inspect` 只读，不生成或覆盖图；不带鱼种的只读检查仅用于另行授权的全量维护，不能作为每次新增鱼的固定步骤。原图不会被缩略图工具修改。`--check` 检查存在性、可解码、WebP、尺寸、比例和透明通道；不能替代人工核对鱼的身份、颜色与细节。

开发工具需要 Python/Pillow、Node.js；浏览器脚本复用本地 Playwright，可用 `PLAYWRIGHT_MODULE` 指定已有安装，`CHROME_PATH` 指定本机 Chrome。不设置 `CHROME_PATH` 时使用 Playwright 默认浏览器。工具自身回归：`python scripts/test-inventory-thumbnails.py`。没有新增游戏运行依赖。

## 参数模板与智能跳过

模板中的空值须填写；`背包.图片` 可为 null，表示用户确认暂缺图片。颜色支持游戏现有英文名或六位十六进制色值，生成的钓获提示色与背包底色一致。`特殊属性` 无特殊时填 []，换边停顿时填例如 ["换边前停顿0.3秒"] 并将 `换边停顿秒` 填0.3；其他行为须先讨论。现有两段时间也可按顺序填 `每段秒` 数组。工具复用真实鱼种验证器；只输出 JSON 或独占创建指定草稿，不自动改名单，不覆盖已存在文件。无图或文件不存在会提示素材未完成，参数通过不代表图片验收通过。

生成缩略图时，只处理 `--fish` 指定的本次鱼。工具保存 `.webp.meta.json`：原图/成品 SHA-256、尺寸、裁剪方式、编码/缩放设置及 Pillow 版本。内容与设置未变、成品可解码且比例/透明度检查通过，输出 `skipped`，图片和记录均不写入。变化或损坏时只重建指定图；默认继承记录的裁剪方式，`--no-crop-transparent` 可明确取消，`--force` 可强制重建。

指定图已有缩略图但没有记录时，先与按当前原图/设置得到的像素逐一比对；一致则 `adopted`，仅为这张图建立记录，不改图片字节/时间。不一致则重建该指定图。此兼容机制仅在该鱼被单独授权处理时使用，不能用来顺带维护旧图。生成图片与记录使用临时文件后原子替换，原图保持原样；`--check` 不补记录，已有记录过期或损坏时返回失败。

## 有界网络操作

`node scripts/git-network.cjs fetch` 同步远端 main；`node scripts/git-network.cjs push` 推送当前工作分支。每个命令默认20秒，可用 `--timeout-ms 10000` 调整（100–60000毫秒），超时清理进程及子进程；若系统权限阻止清理，最多另等5秒便报告 PID 和错误并停止，不进入备用上传。整个流程预算180秒（另留清理时间）。禁止交互式凭据等待，不修改全局 Git 配置。认证失败或分支冲突直接退出；网络失败才通过 `gh api` 检查 GitHub API，并返回明确诊断，默认不通过 API 写入。

确认诊断后可加 `--api-fallback`：fetch 只在远端提交已完整存在本地时更新 `origin/main`；缺少对象就失败，必须另行取得完整提交后再开发。push 只允许干净工作区的普通工作分支，远端必须是本地祖先，最多20个无签名线性提交；逐一核对 blob/tree/commit SHA，复查远端与主分支未变化后以 `force:false` 向前更新并核对最终 SHA。不支持的提交格式、并发变化、超时均停止，不覆盖分支。备用写入需要已配置的 GitHub CLI 权限；这不能根治网络连接问题，但能限制无效等待。

在限制进程管理的沙箱中，超时/清理测试需要允许终止本任务子进程的执行环境；不能忽略权限错误后继续上传。验收报告和截图只保存在被 Git 忽略的 `.qa/`，不作为游戏存档。
